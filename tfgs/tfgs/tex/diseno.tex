\subsection{Descripción del diagrama de clases}

\subsubsection{1. Clases principales}

\paragraph{\qquad KeyboardControlator} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Es la clase central del proyecto ya que se encarga de la coordinación entre todos los teclados.
	\item Maneja el cambio del tipo de teclado y de los idiomas.
	\item És el único que puede escribir en el \textit{TMP\_ImputField}, esto centraliza esta función para no tenerla desperdigada entre los teclados.
\end{itemize}


\paragraph{\qquad Keyboard} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Es el representante de cada uno de los teclados que hay.
	\item Maneja la lógica compleja necesaria en cada teclado, como por ejemplo ``public void Korean\_Syllable\_Formation(string letter, bool isConsonant, bool notSyllable)'' o ``public void ResetKoreanSyllable()''. Centraliza estas funciones en una sola clase para evitar la creación de scripts diferentes para cada uno de los teclados, y que la actualización en caso de error o mejora no tenga que hacerse 14 veces.
	\item Llama a funciones \textit{KeyboardCoontrolator} para poder escribir.
	
\end{itemize}

\paragraph{\qquad KeyboardButton} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Representa una tecla individual de cada teclado.
	\item Maneja la lógica compleja de cada letra y preparado para cada idioma. Como con el \textit{Keyboard}, es para no tener que hacer una clase para cada las teclas de cada teclado distinto y así que las correcciones y mejoras estén centralizadas.
	\item Asocia a un \textit{TextMeshProGui} para actualizar por software la visualización de las letras y así ahorrar memoria al no tener que crear un botón para cada una de las distintas formas que podría salir una letra(por ejemplo cuando se pulsa para mayúsculas, acentos o ALTGR).
	
\end{itemize}

\paragraph{\qquad ButtonVR y CanvasButton} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Son los encargados de los eventos de las teclas de los distintos tipos de teclados. El \textit{ButtonVR} se encarga de la interacción de los teclados físicos, mientras que el \textit{CanvasButton} se encarga de la interacción de los teclados planos, que son creados con Canvas.
	\item Emiten eventos (onPress, onRelease) y controlan audio y colisiones.
	\item Los dos son usado indistintamente por el \textit{KeyboardButton} para otorgar las funcionalidades necesarias a la llamada de eventos y llaman a funciones del \textit{keyboard}.
	
\end{itemize}

\subsubsection{2. Atributos y métodos relevantes}

\paragraph{\qquad Idiomas} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item El \textit{language\_selector} en \textit{KeyboardControlator} incluye: ``English'', ``Spanish'', ``French'', ``German'', ``Russian'', ``Korean'', ``Greece''. Esto es debido a que estos són los únicos idiomas que, por el momento, soporta el Asset.
	\item La nomenclatura de los idiomas está en inglés para facilitar el entendimiento del código a la mayor parte de los desarrolladores que quieran incluir este teclado. Esto presuponiendo que los desarrolladores saben inglés, al tratarse del idioma más usado por esta comunidad.
\end{itemize}


\paragraph{\qquad Método de cambio de idioma} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item La función que realiza esta tarea es el ``public void ChangeLanguage(int index)'' situado en la clase \textit{KeyboardControlator}, y se encarga de ``activar'' y ``desactivar'' los teclados correspondientes de los dos grandes grupos que hay (los físicos y los planos).
	\item Una utilidad muy interesante de este teclado es que automáticamente te pone el idioma de tu Sistema Operativo si está en la lista, en caso contrario se sitúa en el estándar, que es el inglés.
	\item Se ha instaurado un método manual de cambio de idioma mediante el uso de un \textit{TMP\_Dropdown} cuyo cambio de estado dispara un evento que llama a la función.
	
\end{itemize}

\paragraph{\qquad Métodos de cambio de tipo de teclado} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Al ser una de las primeros casos de uso desarrollados, esto se ha desarrollado en dos funciones distintas, cuando podría haberse hecho en una.
	Estas funciones són ``public void ChangeToCanvas()'' y ``public void ChangeToRigid()'' de la clase \textit{KeyboardControlator}. Estas funciones activan o desactivan los objetos raices de los dos tipos de teclados. Entre la desactivación del tipo actual y la activación del nuevo hay 1 segundo de espera, esto es posible gracias al hecho de que las dos funciones desactivan el respectivo objeto y luego llaman a la corrutina ``IEnumerator Change(GameObject g)'', que hace la espera y luego activa el otro objeto.
	\item El Asset está configurado para que siempre salga con los teclados físicos al encender.
	
	\item Se puede cambiar de tipos de teclado manualmente al pulsar los botones correspondientes.
	
\end{itemize}

\paragraph{\qquad Soporte para coreano} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Toda la lógica para este apartado se encuentra en \textit{Keyboard}. Por otro lado, es \textit{ButtonVR} quien se encarga de llamar a estas funciones en concreto viendo si el ``public KeyboardType \_Keyboardtype;'' está en ``Korean''.
	\item Se poseen varias listas y variables encargadas de dar control a la formación de las sílabas usadas en este alfabeto.
	\item Las funciones específicas que se encargan de este idioma son el ``public void Korean\_Syllable\_Formation(string letter, bool isConsonant, bool notSyllable)'', que se encarga de formar las sílabas del hangul mientras se escribe, y el ``public void ResetKoreanSyllable()'', que devuelve al estado base a las variables usadas para controlar la formación de las sílabas (cuando se da a espacio o se borra un carácter).
	
\end{itemize}

\subsubsection{3. Relaciones entre clases}

\begin{itemize}
	\item \textit{KeyboardControlator} tiene asociaciones 1..* con \textit{Keyboard} y sus representaciones visuales (\textit{GameObject}).
	\item \textit{Keyboard} contiene múltiples \textit{KeyboardButton}.
	\item \textit{KeyboardButton} usa \textit{TextMeshProUGUI} para mostrar y actualizar los caracteres en las teclas y también és el \textit{String} \textit{text} de esta interficie lo que se pasa en la llamada a los eventos de escritura.
	\item \textit{ButtonVR} y \textit{CanvasButton} representan diferentes tipos de botones (dependiendo del tipo de teclado) y llaman a métodos en \textit{Keyboard} cuando se activan los eventos. Los eventos específicos de escritura de carácteres son inicializados en \textit{KeyboardButton}.
	\item Relaciones entre botones y eventos están claramente definidas con dependencias (<calls onRelease>), los otros tipos de acciones han sido creadas a mano.
	\item \textit{CanvasButton} implementa funciones de las interficies de \textit{IPointerDownHandler} i \textit{IPointerUpHandler} para el control de eventos. Estas funciones, a su vez, hacen uso del \textit{PointerEventData}, ya que así lo requiere la instancia, pero internamente no se acaba utilizando.
	
\end{itemize}

\subsection{Cambiar de tipo de teclado}

En el próximo diagrama, se mostrará el cambio al teclado plano seguido de un cambio al teclado físico (el orden es debido a que, como ya he dicho, el teclado por defecto aparece como físico). El usuario solo debe tocar un botón predefinido para esto.

\begin{figure}[H]
	\centering
	\includegraphics[width=0.9\textwidth]{SecuenciaCambioTeclados.png}
	\caption{Diagrama de secuencia para el cambio de tipo de teclado}
	\label{fig:diagrama_secuencia_tipo_teclado}
\end{figure}

Como podemos ver, hay muchos actores involucrados en este proceso, desde un \textit{AudioSource} para dar el sonido de pulsar teclas cuando estas se se accionan, hasta un ``GameObject button'' que movemos para ofrecer una experiencia simular el comportamiento de un teclado real.

Estos comportamientos se repiten en cualquier acción que involucre pulsar las teclas, por lo que en los siguientes diagramas resumiremos este proceso uniendo los dos botones (\textit{CanvasButton} i \textit{ButtonVR}) y el Usuario llamará a ``OnTriggerExit(collider) / OnPointerUp(pointerEvent)'' que usará el ``invoke()'' del \textit{UnityEvent}, sin todo lo del sonido ni movimientos, etc.

La corrutina ``Change()'' es de dentro del \textit{KeyboardControlator}, pero lo he separado para ayudar visualmente a entender este proceso.

\subsection{Modificar letras}

Esta característica se ha añadido aquí dentro ya que el modificar el teclado es un proceso indispensable para la escritura en los distintos idiomas, por lo que originalmente lo he incluido en el caso de uso de \textit{Escribir en el teclado}.

Hay varias formas de modificar las letras, dependiendo del idioma. Todas estas se activan al pulsar el botón correspondiente de cada teclado, que cambia el estado de este, a continuación, todas llaman a ``public void Change()'' de \textit{Keyboard}, que a su vez llama a la función tocaya en todos los \textit{KeyboardButton} del teclado activo, que ya se encarga de cambiar las letras dependiendo del estado del teclado.

Vamos a ver el ejemplo de pulsar mayúsculas (en los idiomas que está disponible).

\begin{figure}[H]
	\centering
	\includegraphics[width=0.8\textwidth]{Modificar.png}
	\caption{Diagrama de secuencia de la modificación de las letras de un teclado}
	\label{fig:diagrama_secuencia_modificación_letra}
\end{figure}

Como podemos ver en la figura, el \textit{KeyboardButton} comprueba cada vez que se le llama a la función ``Change()'' el estado del teclado, por lo que hace que el teclado que se use de igual, lo importante es que exista o no el botón que cambie este estado. En las secuencias de las otras maneras de cambiar el estado del teclado solo se diferencian de esta en cual es la funcion del \textit{Keyboard} que llama el \textit{CanvasButton} o el \textit{ButtonVR} independientemente. Las acciones de poner los distintos acentos hacen lo mismo, pero con una función distinta del \textit{KeyboardControlator}.

el ``text'' del \textit{TextMeshProUGUI} es lo que las teclas muestran para saber que letra representan y lo que se cambia en esta acción.
