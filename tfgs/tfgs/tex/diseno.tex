\section{Introducción}
\subsection{Objetivos}
En esta sección trataremos de describir los objetivos principales del diseño del teclado virtual multilingüe para VR lo más detalladamente posible.

El primer objetivo se trata de garantizar la correcta escritura de los siete idiomas seleccionados y en los dos tipos de teclado, con soporte para cambios entre lenguas y tipos, por supuesto.

El segundo objetivo conlleva diseñar una interfaz intuitiva que facilite la interacción tanto con mandos como con hand tracking.

Como último objetivo, pero no por ello menos importante, es imprescindible conseguir que el software creado se integre en cualquier proyecto de Unity que utilice VR, ya que se trata de un Asset. 

\subsection{Relación con el análisis}
%"Se parte del diagrama de dominio (Sección X.Y) y los casos de uso (Sección X.Z) para derivar el diseño detallado."
El diseño va a proceder y extender el análisis previo (Capítulo 4), donde se identificaron casos de uso, se creó una base de modelo de dominio y se establecieron los requisitos técnicos.

En cuanto a los casos de uso, se consideró clave el cambio de idioma, la alternancia entre teclados físicos/planos y el soporte para caracteres especiales.

Por el lado del modelo de dominio, se van a extender las clases propuestas para la correcta integración con Unity y el seguimiento de los principios SOLID. También cambiarán el nombre de las clases para que, si alguien que no hable español lo quiere usar, sepa un poco de qué se trata. Más adelante se detallará todo esete cambio.

Los requisitos técnicos ya se evaluaron y explicaron en la sección de viabilidad (Capítulo 3).

\section{Diseño de la Arquitectura}
\subsection{Arquitectura del sistema}
\subsubsection{Estilo arquitectónico}

El sistema pone en marcha una arquitectura de capas optimizada con patrones enfocados en eventos, creada específicamente para las exigencias singulares de la realidad virtual multilingüe. Incorpora tres perspectivas complementarias:

\begin{enumerate}
	\item \textbf{Arquitectura en capas:}
	\begin{itemize}
		\item Capa de Presentación: Componentes Unity (UI Canvas, 3D Objects)
		\item Capa de Dominio: Lógica de negocio (gestión de idiomas, formación de caracteres)
		\item Capa de Infraestructura: XR Interaction Toolkit, OpenXR
	\end{itemize}
	\item \textbf{Patrón MVC Adaptado:}
	\begin{itemize}
		\item Modelo: Clases \textit{Keyboard} y \textit{KeyboardButton} (almacenan estado y reglas de idiomas)
		\item Vista: Prefabs de teclados físicos/planos y \textit{TMP\_InputField}.
		\item \textit{KeyboardControlator} (orquesta la interacción).
	\end{itemize}
	\item \textbf{Event-Driven:}
	\begin{itemize}
		\item Eventos Unity (onPress, onRelease) para interacciones
		\item Delegados C\# para comunicación entre componentes
	\end{itemize}
\end{enumerate}

\subsection{Descripción del diagrama de clases}

\subsubsection{1. Clases principales}

\paragraph{\qquad KeyboardControlator} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Es una de las clases centrales del proyecto ya que se encarga de la coordinación entre todos los teclados.
	\item Maneja el cambio del tipo de teclado y de los idiomas.
\end{itemize}

\paragraph{\qquad KeyboardWritter} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Es la otra clase central del proyecto ya que es la encargada de escribir en el \textit{TMP\_ImputField}, función principal de cualquier teclado.
	\item Maneja también la visualización del texto dentro del \textit{TMP\_ImputField}.
	\item Centraliza la escritura al no estar esta capacidad desperdigada entre los teclados.
\end{itemize}

\paragraph{\qquad Keyboard} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Es el representante de cada uno de los teclados que hay.
	\item Maneja la lógica compleja necesaria en cada teclado, como por ejemplo ``public void Korean\_Syllable\_Formation(string letter, bool isConsonant, bool notSyllable)'' o ``public void ResetKoreanSyllable()''. Centraliza estas funciones en una sola clase para evitar la creación de scripts diferentes para cada uno de los teclados, y que la actualización en caso de error o mejora no tenga que hacerse 14 veces.
	\item Llama a funciones \textit{KeyboardWritter} para poder escribir.
	
\end{itemize}

\paragraph{\qquad KeyboardButton} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Representa una tecla individual de cada teclado.
	\item Maneja la lógica compleja de cada letra y preparado para cada idioma. Como con el \textit{Keyboard}, es para no tener que hacer una clase para cada las teclas de cada teclado distinto y así que las correcciones y mejoras estén centralizadas.
	\item Asocia a un \textit{TextMeshProGui} para actualizar por software la visualización de las letras y así ahorrar memoria al no tener que crear un botón para cada una de las distintas formas que podría salir una letra(por ejemplo cuando se pulsa para mayúsculas, acentos o ALTGR).
	
\end{itemize}

\paragraph{\qquad ButtonVR y CanvasButton} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Son los encargados de los eventos de las teclas de los distintos tipos de teclados. El \textit{ButtonVR} se encarga de la interacción de los teclados físicos, mientras que el \textit{CanvasButton} se encarga de la interacción de los teclados planos, que son creados con Canvas.
	\item Emiten eventos (onPress, onRelease) y controlan audio y colisiones.
	\item Los dos son usado indistintamente por el \textit{KeyboardButton} para otorgar las funcionalidades necesarias a la llamada de eventos y llaman a funciones del \textit{keyboard}.
	
\end{itemize}

\subsubsection{2. Atributos y métodos relevantes}

\paragraph{\qquad Idiomas} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item El \textit{language\_selector} en \textit{KeyboardControlator} incluye: ``English'', ``Spanish'', ``French'', ``German'', ``Russian'', ``Korean'', ``Greece''. Esto es debido a que estos són los únicos idiomas que, por el momento, soporta el Asset.
	\item La nomenclatura de los idiomas está en inglés para facilitar el entendimiento del código a la mayor parte de los desarrolladores que quieran incluir este teclado. Esto presuponiendo que los desarrolladores saben inglés, al tratarse del idioma más usado por esta comunidad.
\end{itemize}


\paragraph{\qquad Método de cambio de idioma} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item La función que realiza esta tarea es el ``public void ChangeLanguage(int index)'' situado en la clase \textit{KeyboardControlator}, y se encarga de ``activar'' y ``desactivar'' los teclados correspondientes de los dos grandes grupos que hay (los físicos y los planos).
	\item Una utilidad muy interesante de este teclado es que automáticamente te pone el idioma de tu Sistema Operativo si está en la lista, en caso contrario se sitúa en el estándar, que es el inglés.
	\item Se ha instaurado un método manual de cambio de idioma mediante el uso de un \textit{TMP\_Dropdown} cuyo cambio de estado dispara un evento que llama a la función.
	
\end{itemize}

\paragraph{\qquad Métodos de cambio de tipo de teclado} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Al ser una de las primeros casos de uso desarrollados, esto se ha desarrollado en dos funciones distintas, cuando podría haberse hecho en una.
	Estas funciones són ``public void ChangeToCanvas()'' y ``public void ChangeToRigid()'' de la clase \textit{KeyboardControlator}. Estas funciones activan o desactivan los objetos raices de los dos tipos de teclados. Entre la desactivación del tipo actual y la activación del nuevo hay 1 segundo de espera, esto es posible gracias al hecho de que las dos funciones desactivan el respectivo objeto y luego llaman a la corrutina ``IEnumerator Change(GameObject g)'', que hace la espera y luego activa el otro objeto.
	\item El Asset está configurado para que siempre salga con los teclados físicos al encender.
	
	\item Se puede cambiar de tipos de teclado manualmente al pulsar los botones correspondientes.
	
\end{itemize}

\paragraph{\qquad Soporte para coreano} 
\hfill \break % Fuerza salto de línea después del título

\begin{itemize}
	\item Toda la lógica para este apartado se encuentra en \textit{Keyboard}. Por otro lado, es \textit{ButtonVR} quien se encarga de llamar a estas funciones en concreto viendo si el ``public KeyboardType \_Keyboardtype;'' está en ``Korean''.
	\item Se poseen varias listas y variables encargadas de dar control a la formación de las sílabas usadas en este alfabeto.
	\item Las funciones específicas que se encargan de este idioma son el ``public void Korean\_Syllable\_Formation(string letter, bool isConsonant, bool notSyllable)'', que se encarga de formar las sílabas del hangul mientras se escribe; el ``public void ResetKoreanSyllable()'', que devuelve al estado base a las variables usadas para controlar la formación de las sílabas (cuando se da a espacio o se borra un carácter); ``private void FormKoreanSyllable(string finalConsonant = "")'', que convierte los componentes individuales en un carácter Hangul completo utilizando cálculos Unicode (código base 0xAC00); y ``private void HandleInitialInput(string letter, bool isConsonant)'', ``private void HandleVowelInput(string letter, bool isConsonant)'', ``private void HandleFinalInput(string letter, bool isConsonant)'' que son funciones para manejar la introducción de vocales o consonantes.
	\item El sistema sigue el proceso estándar de composición Hangul: consonante inicial + vocal + (opcional) consonante final, traduciendo esta combinación a su correspondiente carácter Unicode.
	
\end{itemize}

\subsubsection{3. Relaciones entre clases}

\begin{itemize}
	\item Tanto \textit{KeyboardControlator} como \textit{KeyboardWritter} tienen asociaciones 1..* con \textit{Keyboard} y sus representaciones visuales (\textit{GameObject}).
	\item \textit{Keyboard} contiene múltiples \textit{KeyboardButton}.
	\item \textit{KeyboardButton} usa \textit{TextMeshProUGUI} para mostrar y actualizar los caracteres en las teclas y también és el \textit{String} \textit{text} de esta interficie lo que se pasa en la llamada a los eventos de escritura.
	\item \textit{ButtonVR} y \textit{CanvasButton} representan diferentes tipos de botones (dependiendo del tipo de teclado) y llaman a métodos en \textit{Keyboard} cuando se activan los eventos. Los eventos específicos de escritura de carácteres son inicializados en \textit{KeyboardButton}.
	\item Relaciones entre botones y eventos están claramente definidas con dependencias (<calls onRelease>), los otros tipos de acciones han sido creadas a mano.
	\item \textit{CanvasButton} implementa funciones de las interficies de \textit{IPointerDownHandler} i \textit{IPointerUpHandler} para el control de eventos. Estas funciones, a su vez, hacen uso del \textit{PointerEventData}, ya que así lo requiere la instancia, pero internamente no se acaba utilizando.
	
\end{itemize}

\subsection{Insertar carácter}

En este punto trataremos del proceso hasta la llamada a \textit{KeyboardWritter}, que se ha destripado en el punto anterior.

Aquí se contemplará todo el proceso que sigue cualquier carácter, incluidos los coreanos y sus transformaciones.

\subsubsection{Primer fragmento}

\begin{figure}[H]
	\centering
	\includegraphics[width=0.9\textwidth]{AñadirCaracter1.png}
	\caption{Primer fragmento del diagrama de secuencia que muestra el proceso para añadir un carácter}
	\label{fig:diagrama_añadir_caracter_1}
\end{figure}

En este fragmento, lo primero que se puede ver como al pulsar el botón de un carácter, dependiendo que tipo de teclado sea, se llama a una función, con unas variables concretas, o otra. En un teclado normal añadimos el carácter y ya está, pero en el caso del coreano se tiene que empezar un proceso por el cual se tienen que formar sílabas en el caso de que se pueda.

En la función \textit{Korean\_Syllable\_Formation}, que se componen de una consonante inicial, una vocal intermedia y de otra posible consonante final. Primero mira si el carácter es ``silabable'', es decir, que es apto para la formación de sílabas, si no lo es simplemente lo añadimos y devolvemos el estado al inicial, ya que es posible que ya hubiéramos empezado el proceso de formar las sílabas. Por otro lado si es apto, comprobamos el paso en la formación de las sílabas en el que nos encontramos, y llamamos a la función encargada de procesar cada paso.

En el primer paso de la formación de sílabas, la función encargada comprueba si la letra es consonante o no, es decir, si es vocal o consonante. En caso de ser vocal, una sílaba no puede empezar por una, así que simplemente añado la letra y ya, no toco el estado porque ya estoy al inicio. En el otro caso, es decir, cuando es una consonante, miro si es una consonante válida y, solo si lo es, avanzo de estado guardando esta letra como componente inicial de la posible sílaba, finalmente escribo este carácter.

\subsubsection{Segundo fragmento}

\begin{figure}[H]
	\centering
	\includegraphics[width=0.6\textwidth]{AñadirCaracter2.png}
	\caption{Segundo fragmento del diagrama de secuencia que muestra el proceso para añadir un carácter}
	\label{fig:diagrama_añadir_caracter_2}
\end{figure}

Esta es la parte que resta del diagrama de arriba, se incluyen las otras funciones relacionadas a la formación de las sílabas con las que se escribe en Hangul.

En el segundo paso de la formación de las sílabas, la función encargada, como en la primera parte, mira que tipo de letra es, vocal o consonante, ya que se necesita otra vocal en este momento para formar una sílaba. Si es consonante, pos nada, reseteamos el estado y lo tratamos como si fuera del primer paso llamando a la función encargada de este. En las vocales se actúa como en se hacia con las consonantes del primer paso, es decir, comprobar si es una vocal válida para la formación; si es válida, pasamos de paso, guardamos el carácter como segundo componente de la sílaba y la formamos; en caso de no ser apto, reseteamos el estado y rellamamos la función \textit{Korean\_Syllable\_Formation}.

En el paso final, comprobamos que sea tanto consonante, como que esta sea válida en esta fase. Si las dos comprobaciones salen positivas, guardamos esta letra como componente final de la sílaba, la formamos y reseteamos el estado, debido a que ya no se pueden añadir caracteres nuevos a la formación. En caso de que alguno de negativo, reseteamos el estado y rellamamos la función \textit{Korean\_Syllable\_Formation}.

La función encargada de formar en si las sílabas, se le pasa una variable booleana, para saber si tiene o no consonante final que contemplar. Se sacan todos los indices de los carácteres que forman la sílaba, teniendo en cuenta que si no hay consonante final, se le da valor 0 por defecto a este índice, para no entorpecer en la creación de las sílabas. Si no hay errores en ninguno de los índices, se hace un pequeño cálculo matemático para sacar el código unicode de la sílaba a usar; luego se borra el último caracter, ya que se trata del estado anterior que queremos sustituir; y escribimos la sílaba.

El reseteo del estado de las sílabas lo lleva a cabo la función \textit{ResetKoreanSyllable}, que simplemente crea un nuevo \textit{KoreanComposition}, para sustituir el anterior.
